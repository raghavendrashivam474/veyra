# S2.2 Research Note — Evidence & Confidence Aggregation

## 1. Context & Research Problem
S2.1 delivered deterministic observation reconciliation (`ReconciledTrait`), answering **what** value is chosen when multiple observations compete.

S2.2 addresses the explainability requirement:
> **Why does Veyra believe a particular trait value?**

Collapsing multiple observations into a bare confidence score (e.g. `hair.color = dark_brown (0.89)`) is insufficient for trustworthy identity modeling. S2.2 creates an explainable assessment layer that pairs reconciled trait values with structured supporting and conflicting evidence.

---

## 2. Core Architectural Distinction: Confidence vs. Evidence

A fundamental principle established in S2.2:
- **Confidence is a scalar assessment score** ($0.0 \le c \le 1.0$), reflecting estimated certainty.
- **Evidence is structured provenance data** (source model, reference material, bounding boxes, detection metrics, attention weights).

Furthermore, **absence of evidence is semantically distinct from low confidence**:
- `has_evidence == False` indicates that no perception model has observed this trait on any reference material.
- `confidence == 0.1` indicates that perception occurred, but certainty is weak or severely contradicted.

---

## 3. Evidence Domain Model

Defined in `src/veyra/domain/evidence.py`:

```python
@dataclass(frozen=True, slots=True)
class EvidenceRecord:
    observation_id: ObservationId
    reference_id: ReferenceId
    source: str
    confidence: Confidence
    evidence_payload: dict[str, Any]

@dataclass(frozen=True, slots=True)
class TraitAssessment:
    trait: TraitName
    selected_value: TraitValue
    aggregate_confidence: Confidence
    supporting_evidence: tuple[EvidenceRecord, ...]
    conflicting_evidence: tuple[EvidenceRecord, ...]
    rationale: str
```

### Key Invariants & Capabilities:

1. Provenance Preservation: EvidenceRecord retains exact observation IDs, reference IDs, model tags (source), and 
   model-specific   metadata (evidence_payload).
2. Source Diversity: The source_diversity property measures how many distinct perception engines 
   (e.g. qwen-vl-72b, insightface-v3, human-annotation) contributed to the assessment.
3. Structured Rationale: A deterministic human-readable string explicitly explains the basis of selection and 
   notes the presence and values of any conflicting evidence.
4. Immutability: All evidence containers are frozen tuples.

## 4. Aggregation Baseline (BaselineEvidenceAggregator)

The default aggregation strategy transforms a ReconciledTrait into a TraitAssessment:

1. Maps supporting domain observations to frozen EvidenceRecord instances.
2. Maps conflicting domain observations to EvidenceRecord instances.
3. Synthesizes a deterministic rationale string detailing observation count, conflict count, conflicting alternative values, and 
   source diversity.

## 5. Application Layer Integration

RepresentationService now provides:

- assess_observations(observations, ...): Reconciles and aggregates arbitrary observation lists.
- assess_traits(representation, ...): Produces explainable trait assessments directly from a CharacterRepresentation aggregate.

-  Confidence aggregation is explainable and deterministic.
-  Supporting and conflicting evidence records preserved separately.
-  Multi-source provenance preserved across models.
-  Duplicate observations handled without dropping records.
